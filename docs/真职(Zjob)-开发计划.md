## 一、整体架构设计

### 1.1 架构原则

- **API优先**：后端统一提供 RESTful API（FastAPI 自动生成 OpenAPI 文档），所有前端端共用同一套接口，避免重复开发。
- **跨端复用**：前端采用跨端框架统一开发，一套代码编译到 Web / 小程序 / APP，最大化复用业务逻辑与 UI 组件。
- **渐进式上端**：后端与数据层先行，Web 端先验证，小程序次之，APP 最后补齐。
- **数据中台**：数据采集、清洗、存储独立于业务层，作为数据中台统一供给各端。

### 1.3 技术选型

| 层级 | 技术选型 | 选型理由 |
| --- | --- | --- |
| **Web 前端** | React 18 + Next.js 14 + TypeScript | SSR 支持 SEO；React 语法与 Taro 共享组件层，三端统一技术栈 |
| **小程序前端** | Taro 4（React 语法） | 一套代码编译微信小程序，与 Web 共享业务逻辑和 UI 组件 |
| **APP 前端** | Taro 4 + React Native 0.74 | 跨平台编译 iOS + Android，复用小程序 80%+ 代码 |
| **跨端状态管理** | Zustand | 轻量、React 全生态兼容（Web/小程序/APP 通吃），无样板代码 |
| **后端框架** | Python 3.12 + FastAPI | 异步高性能 API；与爬虫/AI 数据处理统一 Python 技术栈 |
| **API 网关** | Nginx + JWT 鉴权 | 轻量、稳定、统一鉴权 |
| **主数据库** | MySQL 8.0 | 公司结构化数据存储 |
| **搜索/口碑** | Elasticsearch 8 | 全文检索 + 口碑数据聚合 |
| **缓存** | Redis 7 | 热点公司缓存、搜索缓存、会话管理 |
| **消息队列** | Redis Stream | 复用 Redis 基础设施，无需额外运维 RabbitMQ |
| **对象存储** | 腾讯云 COS | 公司 Logo、截图等静态资源 |
| **爬虫引擎** | Python + Playwright + Scrapy | 动态渲染 + 分布式爬取 |
| **监控告警** | Sentry | 全端（Web/小程序/APP/后端）统一错误监控与崩溃收集 |
| **部署** | Docker + 腾讯云 CVM | 容器化部署，弹性扩缩 |

### 1.4 跨端代码复用策略

```
zjob-monorepo/
├── packages/
│   ├── shared/              # 跨端共享层
│   │   ├── api/             # API 请求封装（各端适配）
│   │   ├── types/           # TypeScript 类型定义
│   │   ├── utils/           # 工具函数（格式化、计算等）
│   │   ├── constants/       # 六维度配置、评估项定义
│   │   └── components/      # 跨端 UI 组件（维度卡片、雷达图等）
│   ├── web/                 # Web 端专属逻辑 + 页面
│   ├── miniapp/            # 小程序端专属逻辑 + 页面
│   └── app/                 # APP 端专属逻辑 + 页面
├── server/                  # 后端服务
├── crawler/                 # 爬虫引擎
└── docker-compose.yml
```

**复用率目标**：业务逻辑与数据模型 100% 共享，React 组件（维度卡片、雷达图、搜索栏等）三端 80%+ 共享，端专属代码 < 20%。

| SSR/预渲染 | 首屏 SSR（Next.js App Router）提升 SEO 和加载速度 |
| 响应式布局 | 移动端适配（销售员可能用手机打开 Web 链接） |
| CDN 静态资源 | 公司 Logo、图片走 CDN 加速 |

### 6.2 小程序端

| 要点 | 说明 |
| --- | --- |
| 分包加载 | 六维度详情页独立分包，减少主包体积 |
| 小程序码限制 | 小程序码参数长度有限，公司ID需短链映射 |
| 订阅消息 | 需用户主动订阅，口碑更新提醒需引导授权 |
| 合规审核 | 小程序内容需符合微信平台规范，口碑内容需过滤敏感词 |

### 6.3 APP 端

| 要点 | 说明 |
| --- | --- |
| 原生能力 | 推送（APNs/FCM）、分享、扫码需调用原生模块 |
| 包体积控制 | RN Bundle 拆分、图片资源压缩、按需加载 |

## 九、风险与应对

| 风险 | 影响 | 概率 | 应对措施 |
| --- | --- | --- | --- |
| 爬虫被反爬封禁 | 数据采集中断 | 高 | IP代理池 + 请求限频 + 多账号轮换 |
| 小程序审核被拒 | 上线延迟 | 中 | 提前了解微信内容规范、口碑内容预审过滤 |
| APP Store 审核被拒 | 上线延迟 | 中 | 提前对接审核指南、准备申诉材料 |
| 跨端框架兼容问题 | 开发效率降低 | 中 | 核心组件先验证三端兼容性再大规模开发 |
| 数据量增长性能瓶颈 | 接口响应变慢 | 中 | Elasticsearch 扩容 + Redis 缓存 + 分库分表预案 |
| 人员不足导致延期 | 交付推迟 | 中 | 优先 P0 功能，P1/P2 功能可跨阶段调整 |
